## Overview

This is a **React Native TurboModule** library providing Naver OAuth authentication for iOS and Android. It is a fork of `@react-native-seoul/naver-login`, rewritten to target the New Architecture (Fabric + TurboModules) using Kotlin (Android) and Objective-C++ (iOS). The package structure is generated by `create-react-native-library` v0.62.0 with `turbo-module` + `kotlin-objc` preset.

The example app in `example/` is a Yarn workspace that points to the local library and also supports Web via Vite + `react-native-web`.

```bash
# Release

```

## Architecture

### TurboModule Codegen Flow

The JS↔Native bridge is driven by codegen. The spec lives in `src/NativeNaverLogin.ts`:

```log
src/NativeNaverLogin.ts   ← TypeScript spec (TurboModule interface)
        │
        ▼
  codegenConfig (package.json)
        │  name: "NaverLoginSpec"
        │  jsSrcsDir: "src"
        │
        ▼
  iOS generated: NativeNaverLoginSpecJSI      (C++)
  Android generated: NativeNaverLoginSpec.java (Java/Kotlin)
```

Any new method exposed to JS **must** be declared in `src/NativeNaverLogin.ts` first. Codegen runs automatically during `pod install` (iOS) and Gradle sync (Android).

### Source Layout

| Path                      | Purpose                                                     |
| ------------------------- | ----------------------------------------------------------- |
| `src/NativeNaverLogin.ts` | JS-facing TurboModule spec (single source of truth)         |
| `src/index.tsx`           | Public API re-exports                                       |
| `src/*.native.tsx`        | Native-platform implementations (Metro picks over `.tsx`)   |
| `src/*.tsx`               | Web / fallback implementations                              |
| `ios/NaverLogin.h`        | ObjC interface, imports `<NaverLoginSpec/NaverLoginSpec.h>` |
| `ios/NaverLogin.mm`       | ObjC++ implementation, calls `getTurboModule:`              |
| `android/`                | Kotlin Android module, namespace `com.naverlogin`           |
| `lib/`                    | Build output (gitignored); generated by `bob build`         |

### Platform-specific Notes

**iOS** — The podspec (`NaverLogin.podspec`) uses `install_modules_dependencies(s)` which handles New Architecture linking automatically. The Naver iOS SDK must be added as a pod dependency when implementing authentication.

**Android** — `android/build.gradle` uses `minSdkVersion: 24`, `compileSdkVersion: 36`, Kotlin 2.0.21. The Naver Android SDK (Maven) must be added to `android/build.gradle` dependencies when implementing authentication.

### Build System

- **`react-native-builder-bob`** compiles `src/` → `lib/` with two targets:
  - `module` (ESM, `lib/module/`)
  - `typescript` (type declarations, `lib/typescript/`)
- **Turbo** (`turbo.json`) provides build caching for `build:android` and `build:ios` CI tasks.
- **Trunk** is the linter orchestrator. Pre-commit: `trunk-fmt-pre-commit`. Pre-push: `trunk-check-pre-push`.

### Monorepo / Workspace

Root = library package. `example/` = Yarn workspace. Always run commands that affect the example from the root using `yarn example <cmd>`.

## Implementing Naver Login

See `docs/plans/2026-05-07-naver-login-turbomodule.md` for the full step-by-step plan. High-level summary:

1. Replace `src/NativeNaverLogin.ts` spec methods with Naver auth API (`initialize`, `login`, `logout`, `deleteToken`, `getProfile`)
2. Implement corresponding methods in `ios/NaverLogin.mm` using `naveridlogin-sdk-ios` CocoaPod
3. Implement corresponding methods in `android/` using `com.navercorp.nid:oauth`
4. Update `src/index.tsx` exports and add platform wrapper in `src/NaverLogin.native.tsx`
